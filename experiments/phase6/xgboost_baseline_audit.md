# Phase 6A: XGBoost Baseline Reproducibility & Leakage Audit

A comprehensive methodology and code-level audit was performed on the Phase 6 XGBoost configuration (`run_full_validation_xgb.py` and `train_xgb_matcher.py`) prior to authorizing its use for final test inference.

## 1. Training Dataset & Leakage Status
* **S1 Records Used for Training:** Exactly the 1,500 records specified in `experiments/dev_s1_ids.txt`.
* **Validation Set Leakage:** **None.** The `train_frozen_model()` function executes entirely independently from the validation evaluation loop. The model is trained and frozen before the 220,683-S1 validation IDs (`experiments/val_s1_ids.txt`) and their corresponding Ground Truth sets are ever loaded. No validation labels contribute to the XGBoost gradients or feature splits.
* **Threshold Selection Leakage:** **None.** The decision threshold of `0.90` is cleanly hardcoded during the full-validation script. It was derived strictly from a completely separated 3-Fold Cross-Validation run on the 1,500-S1 dev set, where thresholds were selected using purely out-of-fold probability predictions.

## 2. Feature Definitions
The feature matrix is strictly identical to the baseline Logistic Regression, utilizing the 15 `extract_lr_features`:
1. `name_exact` 
2. `name_canonical_exact` 
3. `name_tok_jac` 
4. `name_char_jac` 
5. `name_len_diff` 
6. `addr_exact` 
7. `addr_missing` 
8. `addr_tok_jac` 
9. `addr_char_jac` 
10. `addr_num_jac` 
11. `addr_len_diff` 
12. `postal_overlap` 
13. `salient_addr_jac` 
14. `is_s2` 
15. `country_match`

## 3. XGBoost Hyperparameters & Standardization
The model is strictly deterministic and dynamically balanced:
* **Architecture:** `XGBClassifier`
* **Tree Parameters:** `n_estimators=100`, `max_depth=6`, `learning_rate=0.1`
* **Objective:** `eval_metric='logloss'`
* **Random Seed:** `random_state=42`
* **Class Weighting:** `scale_pos_weight = (len(y_train) - sum(y_train)) / sum(y_train)` (Dynamically calculated based on the generated candidates).

## 4. Blocker Integrity
* **Keys:** `CFG1_NoTwoTok_KeyE` is strictly hardcoded inside the `query_custom_s1` call.
* **Budget Limit:** Hardcoded to `K=100`.
* **Candidate Pool Integrity:** The model is fed exactly the `ranked_budget` output from the blocker. No Ground Truth pairs are injected into the feature matrix unless the blocker explicitly retrieved them. The 150,612 pairs known to be missed by the blocker remain strictly missed.

## 5. Result Verification
The Phase 6 full validation results are confirmed to be generated by this uncompromised pipeline:
* **Macro F0.5:** `0.8031`
* **TP / FP / FN:** `518,469` / `32,214` / `245,123`

## AUDIT VERDICT: PASS ✅
The Phase 6 XGBoost baseline exhibits zero data leakage, perfectly adheres to the experimental methodology, and utilizes a completely fair held-out validation setup. The codebase is deterministic and entirely ready for deployment to the final test set.
